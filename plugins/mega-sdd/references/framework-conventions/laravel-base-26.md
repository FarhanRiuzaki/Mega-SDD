# RECON / base-laravel-26 Starterkit Convention Pack

Project-specific overrides for Farhan's **RECON / base-laravel-26** Laravel 12 starterkit. Extends `laravel.md`; this pack's rules override on conflict.

**Stack**: Laravel 12 + Jetstream (Livewire choice) + Socialstream + Sanctum + Spatie Permission + Spatie ActivityLog + Reverb (WebSockets) + Yajra DataTables + Vuexy (Bootstrap 5) theme + jQuery + Vite.

**Test framework**: PHPUnit 11 (NOT Pest).

**Key project documents**: read `CLAUDE.md` + `AGENTS.md` + `docs/INDEX.md` at the starterkit root BEFORE making any structural changes.

## Naming standards (overrides + additions)

| Concept | Convention | Example |
|---|---|---|
| **Primary key** | **UUID v4 via `$table->uuid('id')->primary()`** (NOT auto-increment BIGINT) | Every new table uses UUID PK |
| **Foreign key** | `$table->foreignUuid('user_id')->constrained('users')->nullOnDelete()` (NOT `foreignId`) | `created_by`, `updated_by` always foreignUuid → users |
| Audit timestamps | Auto-filled by `HasUserStamps` trait (`created_by`, `updated_by` UUID FK to users) | Use trait, don't hand-fill |
| Soft delete | `$table->softDeletes();` on every mutable entity table + `use SoftDeletes` on Model | Default ON |
| Generator action verb | `php artisan make:controller-acl {Name}Controller` (NOT `make:controller`) | Scaffolds full module |
| Controller namespace | Grouped by module folder: `App\Http\Controllers\{Module}` | e.g., `App\Http\Controllers\AppsManagement\ActivityLogController` |
| Resource controller filename | Sometimes shorthand (e.g., `User.php` not `UserController.php`) for Auth-related resources | Match sibling files |
| Form Request namespace | `App\Http\Requests\{Module}\{Action}{Name}Request` | `App\Http\Requests\Auth\StoreLoginRequest` |
| DataTable class | `{Name}DataTable` extends `App\DataTables\BaseDataTable` | `NotificationRuleDataTable` |
| Test class | `{Name}Test` (PHPUnit, NOT Pest); descriptive method names `test_<scenario>` | `test_user_can_login_with_valid_credentials` |
| Permission name | `{ability}.{resource}` lowercase (e.g., `user.edit`, `notification.create`) | Seeded, not hardcoded |
| Activity log description | Past-tense verb + entity (`"created user"`, `"updated notification rule"`) | Spatie ActivityLog convention |

## Mandatory traits per entity

Every NEW domain entity Model SHOULD apply the matching traits from `app/Traits/`:

| Trait | When | Effect |
|---|---|---|
| `HasUuid` | Every new entity | UUID v4 PK, replaces auto-increment |
| `HasUserStamps` | Every mutable entity | Auto-fills `created_by` + `updated_by` UUID FK on save |
| `HasActivityLog` | Every entity touched by audit-requiring users | Dual logging: Spatie ActivityLog (DB) + file audit channel |
| `HasSlug` | Entities needing slug-based URLs (e.g., posts, articles) | Auto-generates slug column from configured source |
| `Cacheable` | Entities with high read-to-write ratio + cacheable queries | Tagged cache invalidation |
| `HandlesNumberInput` | Entities with numeric fields needing client-side input handling | Locale-aware number parsing |
| `AutoSoftDelete` | Custom soft-delete behavior (rare; default `SoftDeletes` usually enough) | (See trait source for spec) |
| `HasCommonFields` | Common boilerplate (?) | (See trait source) |

When adding a new Model: copy a sibling Model file (`User.php` or `NotificationRule.php`), keep the same trait stack unless explicit reason to deviate.

## Required base classes

### `App\Http\Controllers\BaseController`

ALL non-Livewire controllers MUST extend `BaseController` (NOT `Controller` directly). Provides:

- `successResponse(string $message, $data, int $statusCode = 200): JsonResponse`
- `errorResponse(string $message, ...): JsonResponse`
- Common JSON envelope shape: `{ "success": bool, "message": string, "data": ... }`

```php
class ProductController extends BaseController
{
    public function store(StoreProductRequest $request): JsonResponse
    {
        $product = $this->productService->create($request->validated());
        return $this->successResponse('Product created', $product, 201);
    }
}
```

### `App\DataTables\BaseDataTable`

ALL list-view DataTables MUST extend `BaseDataTable` (Yajra-based). Provides:

- Action column generation (show / edit / delete) with per-row permission checks
- Buttons row (`create`, `export`, `print`, `reset`, `reload` by default)
- Action parameter configuration
- Custom button support

```php
class ProductDataTable extends BaseDataTable
{
    protected $route = 'products';
    protected $permission = 'product';
    
    protected $canShow = true;
    protected $canEdit = true;
    protected $canDelete = true;
    
    public function query(Product $model): Builder
    {
        return $model->newQuery();
    }
}
```

## Idioms (project-specific overrides)

- **CRUD generator first** — for new resource modules, use `php artisan make:controller-acl {Name}Controller` AFTER the migration exists. Generator scaffolds: controller + DataTable + Form Requests + 4 views + permissions + route + menu. Reversible via `php artisan crud:rollback {Name}Controller`. Do NOT hand-scaffold what the generator handles.
- **Thin controllers, service delegation** — controllers parse request → call service → return response via `successResponse()` / `errorResponse()`. Business logic lives in `app/Services/`.
- **Form Requests for validation** — separate `Store{Name}Request.php` + `Update{Name}Request.php` per resource. NEVER inline `$request->validate([...])` for non-trivial cases.
- **Permission middleware on every route** — every management route MUST have `->middleware('permission:{ability} {resource}')`. Routes go inside the existing `auth:sanctum + whitelist.host + verified` group in `routes/web.php`. Seed permissions in `database/seeders/`.
- **Activity log via trait, not manual** — use `HasActivityLog` trait on Models. Manual `activity()->log(...)` calls only for system-level events outside Model lifecycle.
- **DataTables for list views** — NEVER hand-render lists with `<table>` + foreach. Use Yajra DataTable extending `BaseDataTable`. Server-side processing always.
- **Notification rules over hardcoded notifications** — for new event-driven notifications, define a `NotificationRule` (DB) targeting the Model+event, not a custom Observer or Listener. The rule engine handles fanout (DB + email + Slack + webhook + broadcast).
- **Broadcast via Reverb** — real-time notifications dispatched via `NewNotification` event on `private-user.{id}` channel; client subscribes via Echo + Pusher-JS protocol. Requires `php artisan reverb:start` running.
- **`use SoftDeletes` always** — every entity table gets `$table->softDeletes();` in migration AND Model uses `SoftDeletes` trait. Hard delete only when business explicitly requires (audit-log immutables).
- **Eager loading mandatory** — use `with(['rel1', 'rel2.nested'])` in service queries. Larastan flags N+1 patterns at PHPStan level 5.
- **PHPUnit 11, NOT Pest** — use `php artisan make:test --phpunit {Name}` (Feature) or `--unit`. Feature tests dominate. Golden file tests for generator (`tests/golden/`).
- **Casts via `casts()` method** [v11+/v12] — when adding casts to NEW Models, use `protected function casts(): array { return [...]; }`. When MODIFYING existing Models, match the sibling Model's style (some legacy still use `$casts` property — don't migrate without coordination).
- **PHPDoc over inline comments** — prefer PHPDoc blocks. Inline comments only when something genuinely complex needs explanation.
- **Enum keys TitleCase** — PHP backed enums use `FavoritePerson`, `BestLake`, `Monthly` casing for cases (NOT SCREAMING_SNAKE).
- **PSR-12 via Pint** — run `vendor/bin/pint --dirty` before commit. No manual formatting.

## Frontend conventions (overrides)

This project is **server-side rendered Blade + Livewire + jQuery** — NOT a Vue/Alpine SPA. Don't introduce JS framework migrations.

- **Vuexy theme components** — UI built on Vuexy (Bootstrap 5). Sibling Blade files show component usage patterns. Reuse existing layout/partials before writing new ones.
- **jQuery + DataTables for lists** — server-side DataTables, NEVER client-side filtering for large datasets.
- **Livewire 3 components** — for interactive forms / wizards. Place in `app/Livewire/` (Laravel 11+ default location).
- **JS init pattern**: 
  ```javascript
  document.addEventListener('DOMContentLoaded', function() {
      // init code here
  });
  ```
  ❌ NEVER use `$(document).ready(function() { ... })` — project convention enforced in code reviews.
- **Confirmations / success dialogs**: SweetAlert2 (`Swal.fire({...})`)
- **Toasts**: Toastr (`toastr.success(...)`)
- **Responsive at mobile (375px) + desktop** — every page MUST work on both. Test responsively before committing.
- **Vite for bundling** — `yarn dev` (HMR), `yarn build` (production). User does NOT see UI changes until `yarn build`. NEVER use `npm`; project uses **`yarn`** exclusively.
- **Highlight.js + marked** for inline code / markdown rendering.

## Hard Rules emitted (in addition to `laravel.md` rules)

```

  path_glob: database/migrations/*.php
  rule_type: CUSTOM
  required_pattern: '\$table->uuid\(.id.\)->primary\(\)|foreignUuid\('
  forbidden_pattern: '\$table->id\(\)|\$table->bigIncrements|foreignId\('

  path_glob: database/migrations/*.php
  rule_type: CUSTOM

  path_glob: app/Http/Controllers/**/*Controller.php
  rule_type: SIGNATURE_RULE
  required_pattern: 'extends BaseController'
  exempt_globs: ['app/Http/Controllers/Controller.php', 'app/Http/Controllers/BaseController.php', 'app/Http/Controllers/Auth/**/*.php']
```

## Forbidden patterns (in addition to `laravel.md` forbidden)

- `$(document).ready(function() { ... })` — use `document.addEventListener('DOMContentLoaded', ...)` (HARD blocking)
- `alert(...)` / `confirm(...)` / `prompt(...)` browser native dialogs — use SweetAlert2 (HARD blocking)
- `console.log(...)` left in committed code — use Toastr for user-facing messages or remove
- `npm` commands in docs / scripts / README — use `yarn` (project lockfile is yarn.lock)
- Pest test syntax (`it('does X', fn() => ...)`) — use PHPUnit (`public function test_does_x(): void`)
- Direct `$table->id()` / `$table->bigIncrements()` / `$table->foreignId(...)` in new migrations — use `$table->uuid(...)` + `$table->foreignUuid(...)`
- Hardcoded permission strings checked inline (`if ($user->role === 'admin')`) — use `permission:{ability} {resource}` middleware OR `$user->can('ability', $resource)` (Spatie integration)
- New `app/Helpers/<custom>.php` file — add to one of the 9 existing helper files matching the domain (`auth_`, `format_`, `storage_`, `flash_`, `ui_`, `cache_`, `settings_`, `activity_`, `utility_`)
- Pattern-matching from `old-reference/` — legacy code, NOT current. Check live equivalent under `app/`
- Custom `app/<NewFolder>/` not in `[Actions, DataTables, Enums, Helpers, Http, Jobs, Listeners, Mail, Models, Notifications, Policies, Providers, Services, Traits, View]` — get approval first
- New Spatie / Laravel composer deps without approval — project pins specific versions; lockfile coordination matters
- Manual obfuscation of generated files — use `php artisan obfuscate:controller` pipeline; commits with "obfuscat" in message skip PHPStan hook intentionally

Errors raised through `app/Services/ErrorResponseService.php` use codes from `app/Enums/ErrorCode.php`:

| Range | Category |
|---|---|
| 1xxx | Validation / input |
| 2xxx | Authentication / authorization |
| 3xxx | Resource not found / conflict |
| 4xxx | External service / integration |

When throwing exceptions: prefer typed Exception classes with explicit ErrorCode → `ErrorResponseService` auto-classifies SQLSTATE errors. When `APP_DEBUG=false`, SQL/bindings/traces stripped from JSON output.

## Notification rule pattern

For NEW event-driven notifications, prefer the rule engine over Observer/Listener:

1. Create a `NotificationRule` row (via UI: `/notification-rules/create`, or via seeder)
2. Specify: target Model + event (`created`, `updated`, `deleting`, custom Eloquent events)
3. Define conditions (jQuery QueryBuilder format: AND within groups, OR between groups)
4. Define recipients (all users / by role / specific users / dynamic relation expression)
5. Choose channels (database / email / Slack / webhook / Reverb broadcast)
6. Throttle settings (per recipient + per rule)
7. Save → `NotificationRuleService` auto-registers Eloquent event listeners at next boot

The engine handles: condition eval, fanout to channels, retry (3 tries, backoff 10s/60s/300s), throttle via `RateLimiter` + `ProcessThrottledNotificationJob`.

Detail: `docs/features/NOTIFICATIONS.md`.

## Notes / pack-specific guidance

- **`old-reference/` is legacy**: any code under `old-reference/` is NOT current. Don't pattern-match from it. Look at sibling files in `app/` for the live pattern.
- **PHPStan baseline (109KB) exists**: there's accepted tech debt in the baseline. Don't try to "fix" baseline items in unrelated PRs — that creates merge conflicts. Resolve baseline items in dedicated cleanup PRs.
- **Helpers are FORCE-LOADED**: 9 helper files autoloaded via composer `files`. Functions are globally available. Adding new helpers: extend an existing file matching the domain, don't create a 10th.
- **Code obfuscation skip rule**: commits with "obfuscat" in message bypass the PHPStan pre-commit hook ON PURPOSE (obfuscated code fails static analysis). Don't include this token in non-obfuscation commits.
- **CRUD generator is reversible**: every file generated by `make:controller-acl` is tracked + reversible via `crud:rollback`. If a generator change breaks something, rollback + regenerate (don't manually patch generated files).
- **Telescope on in dev**: useful for debugging queries/jobs/notifications. Don't commit `.env` changes that enable it in production.
- **Notification rule throttle**: per-rule + per-recipient. Throttled notifications defer to `ProcessThrottledNotificationJob`. Test throttle behavior with `broadcast:test`.
- **Vuexy theme rules**: components live in `resources/views/components/`. Sibling component shows the structure. Don't write raw Bootstrap HTML when a Vuexy component exists.
- **Search Laravel docs via Boost MCP**: use `search-docs` tool from Laravel Boost MCP before falling back to web search — passes installed package versions for version-specific results.
- **`use-yarn-not-npm`**: project lockfile is `yarn.lock` (271KB). `package-lock.json` may exist as artifact but is not authoritative. Always `yarn install` / `yarn dev` / `yarn build`.

## When to deviate from this pack

This pack reflects the **starterkit's** opinions. If the user's actual project (built from this starterkit) needs to:
- Use auto-increment IDs (not UUID) for a specific table → document the exception in `data-mutation-policy.md` (Iter 22) as `[LOCKED]` with rationale
- Use Pest instead of PHPUnit → coordinate with team; PHPUnit suite needs migration
- Use Vue / React frontend → significant deviation; needs ADR

Document deviations in:
- Vault `05-decisions.md` (ADR for architectural choices)
- `constitution.md` (Iter 17) for project-wide rules that override this pack
