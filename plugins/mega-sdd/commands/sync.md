Invoke the `mega-sdd:orchestrate-flow` skill via the Skill tool with `--sync` (plus user flags below).

User arguments: $ARGUMENTS

What this does (per `orchestrate-flow/references/routing-rules.md` §Mode D and spec `docs/superpowers/specs/2026-06-10-living-vault-continuous-sync-design.md`):

1. **Detect change** — union of two channels: `.mega-sdd/codebase/.dirty-paths.jsonl` (in-session Write/Edit journal, even uncommitted) + git movement against the symbol-index `head_commit` (the GROUND freshness stamp).
2. **Changed set** — `scripts/derive-changed-paths.sh --vault <vault>` writes `<vault>/.sync-changed-paths.txt` from git diff (from the symbol-index stamp) ∪ the working tree ∪ the journal (zero model tokens). The symbol index is refreshed by GROUND (`scripts/ground.sh`) and before any re-bind (`rebind-units.sh` rebuilds a stale index first).
2b. **Claim-intersection short-circuit (deterministic).** `Run: bash <plugin-root>/scripts/sync-intersect.sh --cwd=<root> --vault=<vault> --paths=@<vault>/.sync-changed-paths.txt` — exit 0 (`in_sync`: changed set ∩ binding anchors ∪ unit target_files is EMPTY) → stamp freshness, write the one-line SYNC-REPORT.md ("in sync — N changed paths, 0 intersect"), and END the chain here (nothing to re-verdict — proportional verification, zero verification loss: a later bind re-blocks regardless). Exit 4 → proceed. Exit 2 — or ANY other unexpected exit — → fail-closed: proceed with the FULL chain (unknown gate rc is never a pass).
3. **Drift triage** — `detect-drift` scoped to the changed paths; findings stay direction-neutral (code right vs vault stale).
4. **Re-bind + reconcile** — `scripts/rebind-units.sh --cwd=<root> --vault=<vault> --paths=@<vault>/.sync-changed-paths.txt` re-verdicts, with the SAME JIT writers, only the units whose `target_files` ∪ `## Anchors` ∪ per-unit binding anchors meet the changed set (exit 0 = nothing affected; 4 = re-bound — read `gate`; 3 = a writer failed → full re-bind, never in-sync; a CONFLICT closes the gate for the affected units). Units outside the changed set keep their `bolts/U-XXX/binding.json` untouched — this hop does not re-validate them — and an unresolved CONFLICT there still closes that unit's gate at dispatch (invariant #2) until the JIT bind re-verdicts it or `resolve-oq --binding` resolves it (`--full-bind` re-verdicts every unit). Then `plan --reconcile` updates existing unit IDs in place from `bolts/U-*/binding.json` (task_type flips, `status` recomputed via `scripts/compute-unit-staleness.sh`, a unit whose vault home is gone → `superseded`, never duplicates — `skills/plan/references/task-typing.md` §Reconcile pass). It never adds units: a new requirement goes through `diff-vault` → `plan --regenerate`. `execute-bolts --all --lite` then runs only stale/new units (`superseded` skipped). A layout-2 vault → propose `/mega-sdd:migrate-paths --vault-layout=3` first (then `rebind-units.sh --units=all`).

Flags:
- `--dry-run` — show the change summary + proposed chain without executing
- `--auto` — fully autonomous: ONE upfront confirmation, then NO mid-chain questions (decision deferral — see below)
- `--auto-apply=safe` — opt-in: auto-apply the SAFE write-back class only (confidence HIGH + category ∈ name-drift/type-drift/missing-in-vault + claim NOT `[LOCKED]` + code side committed — definition OWNED by detect-drift Step 5; this line mirrors it); everything else queues
- `--no-drift-check` — standard opt-out (passed through)
- `--full-bind` — **audit sinkronisasi penuh = `sync --full-bind`.** Instead of the scoped re-bind of step 4, run the JIT bind over EVERY unit of the vault (`scripts/rebind-units.sh --cwd=<root> --vault=<vault> --units=all`): `derive-unit-claims.sh --units=all` → `write-unit-binding.sh` per unit (fs/symbol claims verdicted by script; `text` claims via ladder E3 verbatim — `skills/execute-bolts/references/jit-bind-and-quarantine.md` §E3, never CONFIRMED-by-absence) → `validate-handoff-binding-units.sh --units=all` (every open CONFLICT is BLOCKING). This is the button for the adoption / BA-QA question *"apakah kode masih sinkron dengan spec?"* — the whole-vault coverage a guarded project otherwise only gets one wave at a time (spec 2026-09-10 §4 degradation b). Output = per-unit `bolts/U-*/binding.json` + the Sync report's Re-bind row with CONFIRMED/CONFLICT/OQ totals; CONFLICTs route to `resolve-oq --binding` like any bind.

Autonomous behavior (`--auto` — decision deferral, per spec §3.7):
- Safe operations run through: changed-set derivation, per-unit re-bind (`rebind-units.sh`), unit reconcile, stale/new bolt execution (every existing bolt gate intact).
- Human-required decisions NEVER pause the chain — they queue into `<vault>/PENDING-SYNC.md` (drift direction calls, write-back drafts, re-bind CONFLICTs). CONFLICTs still close the gate for the affected downstream units (the moat is untouched); the chain completes everything else and reports.
- Drift triage processes changed paths in **descending blast-radius order** when the graph is available (`query-graph.sh` — the call most likely to need a human lands earliest); graph absent → document order, unchanged (advisory ordering only).
- End of run: `<vault>/SYNC-REPORT.md` — change counts, per-phase outcomes, applied-vs-queued patches (with git provenance), conflicts raised, units reconciled/re-executed, the **verify-recommended (transitive impact)** list (`skills/plan/references/task-typing.md` §Reconcile pass step 2.6 — dependents of changed units the hash check cannot see; offered, never auto-run), and the closing staleness verification (`scripts/compute-unit-staleness.sh` re-run; stale count MUST be 0 or explained). One chat line summarizes; the report carries the detail; refreshes `.mega-sdd/graph.json` (cache-warm; non-blocking). When emitted `.claude/rules/mega-sdd-*` files exist and `constitution_hash` changed OR units were reconciled, the report PROPOSES `scripts/emit-claude-rules.sh --write` (offer-only — writing to `.claude/` is user config; never auto-run).
- The next GROUND (M/L entry) re-checks the per-vault state and the session-start state block shows it; open PENDING-SYNC.md items surface in the `/mega-sdd` status view (Lane 0), not in the session-start line.

Hard rails:
- Git state first: repo mid-rebase/merge (probe `git rev-parse --git-path rebase-merge` / `--git-path MERGE_HEAD` — worktree-safe; never the literal `.git/...` path) → STOP with "resolve the git state, then re-run sync" (a changed set derived mid-conflict is garbage).
- The binding CONFLICT gate applies unchanged — sync never bypasses the moat.
- The dirty journal is a HINT; git is always consulted too. Journal consumed via rotate-and-delete (`scripts/derive-changed-paths.sh`): the changed set is written first, then the live journal is rotated to `.consumed-<ts>`; leftover `.consumed-*` files are unioned in and deleted on the next successful run; a failed write leaves the journal alone — never truncated in place (concurrent-session appends land in the fresh journal).
- No change signal detected → report "in sync" and stop (no vacuous re-runs).
- Changed-set derivation failing (`derive-changed-paths.sh` exit 3 — no baseline stamp / git unavailable / write failed) → full JIT re-bind fallback (`scripts/rebind-units.sh --cwd=<root> --vault=<vault> --units=all`, same as `--full-bind`), detect-drift skipped; the journal is NEVER consumed on a failed write.
