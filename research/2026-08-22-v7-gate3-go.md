Bukti lo cukup: ekstraksi netto ~4% sambil menambah loader + fail-mode + satu file parity-sensitive baru, dan "4 kopi" ternyata 2 kopi + 2 parser beda desain. Itu gimmick. ## Fase 3 — contoh vault DISETUJUI

Layout 4 file + `vault.json`, residu 00-index ke frontmatter, OQ terpusat di `constraints.md`, `vault_layout: 2` sebagai marker dual-layout — semua OK. Empat tambahan sebelum implementasi:

1. **Tiap OQ wajib punya `origin`.** Karena OQ tidak lagi hidup di samping konteksnya, tambahkan satu token lokasi per baris, contoh: `- [ ] **OQ-CLINIC-003** [P2] [business] [origin: flows.md#F-U-002]: …`. Grammar-nya masuk `vault_md.parse_open_questions` dan ikut ke `vault.json` (`origin` field). Tanpa ini, resolve-oq dan bind kehilangan locality yang dulu gratis dari per-doc placement — itu regresi grounding, bukan sekadar kenyamanan.

2. **Section header `vault.md` jadi kontrak keras**, bukan konvensi: `## Overview`, `## Architecture`, `## Decisions`, `## Glossary` (opsional) — persis string itu, karena DOC_CODE re-key dari filename ke section. `derive-claims-ledger` dan `derive-vault-json` harus gagal jelas (exit ≠ 0, pesan menyebut header yang hilang) kalau header tidak ada, bukan diam-diam menghasilkan ledger kosong. Masukkan ke template generate-intent sebagai heading yang tidak boleh diubah.

3. **Urutan commit (satu release, tapi bisa di-bisect):**
   - (a) parser + dual-layout read (`vault_md.py` lock dari frontmatter dengan fallback `## Vault Lock Status`; locator active-vault probe `flows.md` lalu `04-flows.md`) + fixtures 4-file di `tests/graph/fixtures/` — layout lama harus tetap hijau di commit ini, nol perubahan perilaku.
   - (b) konsumen re-key: DOCS list (derive-vault-json, claims-ledger, run-analyze), 5 situs glob `04-flows.md`, DOC_CODE by section, certify-artifact identity (`vault.md` OR `00-index.md`), builder emisi (fsd/prd/sit/uat) + string sitasi.
   - (c) `migrate-paths --vault-layout` rung + test migrasi: fixture 7-file klinik → 4-file → `derive-vault-json` output setara `expected-vault.json` (kecuali `doc` field), dan pesan "full re-bind required" tercetak. Dry-run default.
   - (d) generate-intent templates + generation-guide menghasilkan layout baru by default; prose refs (±35 situs audit §5.2) diperbaiki di commit ini.
   - (e) docs: README, CHANGELOG 7.0.0, `upgrade-from-old-version.md`, `paths.md`.
   Test hijau KEDUA tree per commit, `gh run list` sesudah push.

4. **Bukti penutup Fase 3:** (i) blackbox pipeline end-to-end pada `sample-prd-clinic.md` dengan layout baru sampai units; (ii) ukur byte/token total vault klinik before (7 file) vs after (4 file) — gue mau angka, karena klaim "lebih efisien untuk LLM" harus terukur; (iii) trace tier S diulang sekali lagi (tidak boleh berubah, tapi cek).
