Ringkasan program satu halaman diterima — itu yang gue bawa ke tim.

## A. Per-unit model routing + cascade — GO implementasi, ship default ditentukan A/B

Desain disetujui apa adanya (router dari sinyal yang sama, haiku hanya `verify`, unknown tidak pernah turun tier, cascade naik-saja max 1×, `--no-escalate`, `parallel_max` default 4, varian agent file tidak dibangun). Syarat:

1. **Ship kode ≠ ship default.** Implementasikan dengan `model_tiers.bolt_implementer: inherit` sebagai default config (perilaku hari ini, nol regresi kantor). Nilai `auto` mengaktifkan router + cascade. Arm B A/B = `auto`. Flip default ke `auto` hanya setelah A/B lolos kriteria (≥25% hemat token DAN P1 findings ≤ arm A DAN acceptance pass rate sama) — itu gate terpisah, keputusan gue.
2. `model_used` dan `escalated_from` wajib di bolt-report, disalin verbatim dari system prompt implementer (bukti presedens param-vs-frontmatter). Kalau ternyata frontmatter menang, berhenti dan lapor — jangan langsung bangun varian file.
3. Runbook rollout kantor: probe 1-baris `Agent(model:"haiku")` + catatan gateway mega-code harus resolve alias; kalau tidak resolve, `model_tiers:` per-project menetralkan.
4. Urutan commit: (a) router fields + tests, (b) controller execute-bolts + front-door plumbing + config contract + bolt-report fields, (c) model-tiers.md row 22 + docs + CHANGELOG 7.1.0. Test hijau kedua tree per commit.
5. Setelah (c): jalankan A/B klinik, publikasikan hasil di `research/` apa pun hasilnya, berhenti di gate.

## B. Fase 4 markdown diet — GO, urutan dan target

Target agregat pipeline 1-unit **182k → ≤135k tok (−25%)**, diukur tracer yang sama; target per lane dari scoping dipakai sebagai sasaran, bukan janji. Urutan:

| Urutan | Item | Alasan urutan |
|---|---|---|
| 1 | **R5** re-derivasi trace T01/T07 + lane trace bolts-per-unit di harness | prasyarat angka — tanpa ini tiap klaim hemat tidak bisa dibuktikan |
| 2 | **R4** pecah `execute-bolts/SKILL.md` 45 KB → inti dispatch + per-mode refs | terbesar karena dikali jumlah unit; verify-unit tidak boleh memuat squad/parallel/code-gate |
| 3 | **R2** split 5 file bocor (vault-core, review-panel dispatcher-core, chain-execution diagnostics keluar spine, generation-guide sectioning, binding-contract express-half) | restrukturisasi ref, satu file per commit |
| 4 | **R1** dedup keluarga orchestrate ke single-owner + pointer | edit rendah risiko, presedens M-04 |
| 5 | **R3** 5 blob prose → tabel keputusan | terakhir, karena paling rawan kelas carve-out |

Aturan main:
- **Satu R = satu seri commit, tracer before/after per R** ditempel di commit message atau research note. Kalau sebuah R tidak menurunkan token terukur, revert, jangan dipertahankan "karena lebih rapi".
- **Daftar lindung 7 rail (§7 scoping) disetujui**: grammar verdict, halt taxonomy, hard-rule grammar, mandat Mermaid, kontrak layout-2, parity pin packs, plus apa pun yang dibaca script. Tidak disentuh. Untuk R3, Mode D exit-codes jadi **tabel yang dibaca script** (sync-intersect), bukan prose lebih pendek; kandidat R3 lain boleh jadi tabel markdown yang dibaca model selama kondisinya enumeratif.
- **Mirror `derived-position` di routing-rules**: keputusan gue — jadikan pointer + ringkasan ≤5 baris ke owner tunggal. Alasan "intentional" lama harus ditulis ulang kalau masih berlaku; kalau alasannya cuma "supaya tidak perlu load file lain", itu persis leak progressive disclosure yang sedang kita buang.
- Split file tidak boleh menambah file yang di-load bersamaan (split yang hasilnya dua-duanya tetap di-Read = nol hemat). Router SKILL tetap satu-satunya entry.
- Sweep kedua tree + CI per commit, seperti biasa. Skill-triggering tests (tests/skill-triggering) wajib tetap hijau — split ref tidak boleh mengubah kapan skill ter-trigger.
