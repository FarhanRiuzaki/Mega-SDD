# Unit U-001 — Open the three public company-profile routes in the proxy guard

## Goal

Let `/beranda`, `/tentang-kami` and `/kontak` load for any visitor, with or without a session, while every existing guard stays as it is.

## Context (read first)

The PRD pages need no login (PRD §Latar belakang, §Ruang lingkup), but `src/proxy.ts` currently sends every anonymous non-auth path to `/login` and bounces signed-in users off `publicRoutes` to `/home` (context.md#Constraints, constitution C-004). The paths follow the provisional OQ-AR-1 recommendation; `src/proxy.ts` must stay at the Next.js 16 reserved location, so its test sits beside it as `src/proxy.test.ts`.

## Anchors

- src/proxy.ts:7-33 — `proxy()` guard: RefreshTokenError branch, auth-only `publicRoutes` bounce, anonymous → `/login` redirect
- src/proxy.ts:11 — `publicRoutes = ['/login', '/register']` (auth pages, NOT the open public pages)
- next.config.ts:5-13 — `/` → `/home` redirect (left untouched, OQ-AR-1)

## Claims

- C-U001-01 "proxy() is the route guard for page requests" — expect: src/proxy.ts:proxy
- C-U001-02 "root redirect / -> /home is configured in next.config.ts" — expect: next.config.ts — must-exist

## Hard rules

- DO NOT modify next.config.ts
  Source: context.md#Constraints + OQ-AR-1 — the / -> /home redirect stays until the URL question is answered
- DO NOT add new package.json dependencies
  Ref: CLAUDE.md §Stack & Commands — the existing stack (MUI, next/link, react-hook-form, zod, TanStack Query, MSW) covers this unit; allowed_new_deps is empty
- ALWAYS keep the existing /login and /register bounce and the anonymous redirect to /login for every other path (constitution C-004 opens only the three PRD pages)

## Implementation steps

1. Read `src/proxy.ts:7-33` first, then add a separate list of open public paths (`/beranda`, `/tentang-kami`, `/kontak`) that returns `NextResponse.next()` at the very top of `proxy()`, before the RefreshTokenError and session checks, so a visitor with no session or a stale session is never redirected on those pages.
2. Write `src/proxy.test.ts` with `getServerSession` from `next-auth` mocked (use `// @vitest-environment node` if `next/server` needs it) and assert: the three public paths are not redirected for no session, a valid session and a RefreshTokenError session; `/users` without a session still redirects to `/login`; `/login` with a session still redirects to `/home`.

## Migration notes

- **REMOVE**: nothing.
- **KEEP**: the RefreshTokenError cookie-clearing redirect, the `publicRoutes` (`/login`, `/register`) bounce to `/home` for signed-in users, the anonymous redirect to `/login`, and `export const config = { matcher }` exactly as they are.
- **ADD**: an open-public-routes list (`/beranda`, `/tentang-kami`, `/kontak`) checked first, returning `NextResponse.next()` regardless of session state.
