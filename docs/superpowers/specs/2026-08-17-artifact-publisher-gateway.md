**Decisions locked in brainstorm:** (1) topology = office AI gateway, MCP lives there, flow developer → Claude Code (mega-sdd) → gateway; (2) **PUSH model** — mega-sdd is the active side, auto-updates, gateway passively receives; (3) cadence = **Stop-hook debounced** (telemetry pattern: async, fail-open, no-change → no push); (4) payload = **ALL artifacts** (graph, vault, binding, units, KB, codebase-map, symbol index) — internal network + authorized MCP assumed (user to confirm with infra); (5) transport = **plain HTTPS POST, NOT MCP** (publisher is Stop-hook script-plane: deterministic, zero-token, headless-safe; MCP lives on the READ side); (6) **no auto-registration in the plugin's `.mcp.json`** — the gateway URL is office-specific; teams get the same auto-UX by committing a project-scope `.mcp.json` in each office repo.

## What we build (plugin side only)

1. **`scripts/publish-artifacts.sh`** — deterministic publisher:
   - Collects: `.mega-sdd/graph.json`, `vaults/*/` (7 docs, binding.md, `bound/`, `units/`, `bolts/_summary.md`), knowledge-base, `codebase/codebase-map.md`, symbol index.
   - Emits `manifest.json`: `project_id` (normalized git remote), `vault`, `git_head`, `generated_at`, sha256 per file, `graph_meta` (the graph's `_meta.source_hashes` — staleness honesty), and OPTIONAL `work_dir` (BASENAME of the working folder only, never a full path — approved 2026-08-20 on the gateway team's request as a telemetry JOIN-HINT for the :8002 human reader; NEVER an identity key, `project_id` stays canonical).
   - Sends ONLY files whose sha changed since the last push (local stamp `.mega-sdd/.publish-state.json`). **Wire format (pinned 2026-08-20 with the gateway team, their option (b)):** one raw `Content-Type: application/gzip` body — a tar.gz whose FIRST entry at the tar root is the FULL `manifest.json`, followed by the changed files at their manifest paths. No multipart, zero new deps both sides (`curl --data-binary` on ours, streaming raw + shell `tar` on theirs).
   - Exit 0 ALWAYS on network failure (fail-open): queue in `.publish-state.json`, retry next trigger, one log line.
2. **Stop-hook leg** — reuses the existing artifact-change detection + debounce; async; inert unless `publish.gateway_url` is configured.
3. **Credentials — read what mega-code already provisions (source-verified against `mega-code@0.5.0` on npm, 2026-08-20).** mega-code is an EXTERNAL npm CLI: `login` (LDAP, NIP+password) stores/refreshes tokens; `install` writes `~/.claude/settings.json` with `env.ANTHROPIC_BASE_URL=<gateway>` + `apiKeyHelper: "mega-code get-token"`. The publisher therefore needs ZERO new provisioning: **URL** = `$ANTHROPIC_BASE_URL` (settings env is injected into the Claude Code process; the Stop-hook inherits it) with the ingest at `$ANTHROPIC_BASE_URL/mega-sdd/ingest`; **token** = `mega-code get-token` (bounded subprocess, same accessor apiKeyHelper uses; refresh/expiry is mega-code's internal job). Probe ladder (amended at implementation: EXPLICIT beats AMBIENT — an override that loses to the office path would make testing on office laptops impossible): (1) env `MEGA_SDD_PUBLISH_URL`/`MEGA_SDD_PUBLISH_TOKEN` (explicit override, CI/testing); (2) `ANTHROPIC_BASE_URL` set AND `mega-code` on PATH AND `get-token` exit 0 (bounded) → office path; (3) `.mega-sdd/config.yaml` `publish.*` (non-office). No hit / `get-token` non-zero → publisher inert or queue with one log line "run mega-code login". Attribution per NIP happens at the gateway (token is minted per NIP); no PII in artifacts. Superseded on the record: the earlier `~/.mega-code/megasdd-publish.json` credential-file design (invented before reading the source — unnecessary).
4. **Ingest contract + team guide** — `docs/mega-sdd/gateway-mcp-guide.md` (shipped with this spec) is the contract the office team builds the gateway + MCP against.

## Contracts

- **Idempotent ingest**: same sha set → no-op. Storage keyed `project_id`/`vault` @ `git_head`, latest-wins.
- **Read-only + honesty**: external consumers read verdicts as INFORMATION — the moat's gates live only inside mega-sdd; staleness metadata always shipped; the gateway MCP must never mutate.
- **Rejected on record**: MCP-client push (dependency + model-plane for a machine-to-machine job); git-pull transport (user wants active push, near-realtime); bundling the gateway MCP in plugin `.mcp.json` (office-specific URL in a public plugin; env-expansion contractually undocumented — the context7 keyless precedent).

## Tests (when implementation starts)
Manifest determinism · delta-by-sha · fail-open (dead endpoint → rc 0 + queue) · inert-without-config · token-never-logged · debounce (no change → no push) · tar contents match manifest.

## Non-goals
The gateway ingest service and the MCP server itself (the office team's build, per the guide). Cross-project reuse queries from mega-sdd sessions (future, once the office registers the read-side MCP in project repos).

## Amendment v6.19.1 — office-rung detection: "mega-code MANAGES this session", not "mega-code exists" (2026-08-20)

User requirement: **vanilla Claude (direct Anthropic) must never publish; mega-code-managed sessions publish automatically.** The v6.19.0 office rung (`ANTHROPIC_BASE_URL` set in process env AND `mega-code` on PATH) already covers the main case, but leaves one hole: a developer with mega-code merely INSTALLED, running a vanilla/other-gateway session with a foreign `ANTHROPIC_BASE_URL` in the environment, would have the per-NIP token minted by `mega-code get-token` POSTed to that foreign URL — wrong destination AND a token-exfil path (same family as round M1).

**Change (rung 2 only; rungs 1 and 3 untouched).** The office rung arms only when ALL THREE hold, from/against `~/.claude/settings.json` (the file `mega-code install` writes — source-verified v6.19.0):
- **(a) Management signature** — `apiKeyHelper`'s command basename is `mega-code` (quoted absolute paths handled; the same helper command string is then used to mint the token, so signature and mint can never name different binaries — round MINOR-6). Binary-on-PATH alone never arms the rung.
- **(b) Destination from settings** — the gateway URL is `settings env.ANTHROPIC_BASE_URL` (http/https scheme required), NOT the process environment — URL and token share one source of truth, so a foreign env `ANTHROPIC_BASE_URL` can no longer redirect the token.
- **(c) The session is routed there RIGHT NOW** (round MAJOR-2) — the PROCESS env `ANTHROPIC_BASE_URL` must equal the settings URL (trailing-slash-insensitive). This is what makes the gate "mega-code manages this SESSION", not "this machine was once provisioned": a provisioned machine running a vanilla/overridden session (`ANTHROPIC_API_KEY` export, `--settings`, project-settings override) fails (c) and publishes nothing. Known dependency: (c) assumes the Stop hook inherits the settings-injected env (asserted in v6.19.0; the pending publisher↔gateway field test is the checkpoint — if office Stop-hook env turns out not to carry `ANTHROPIC_BASE_URL`, revisit (c) before loosening anything else).
- The ladder becomes fall-through: an armed-but-unsatisfied office probe falls through to rung 3 (`config.yaml publish:`) instead of dead-ending. Disclosed tradeoff (round MINOR-10): a repo-committed `publish:` block is now reachable in strictly more situations on office machines (unmanaged sessions) — it pairs a repo-supplied URL ONLY with the repo-supplied token (cross-rung credential pairing verified impossible); the per-NIP token never rides rung 3.
- Settings parse is python (JSON `utf-8-sig`, `expanduser("~")` → HOME on POSIX / USERPROFILE on Windows python), fail-closed to "not office" on any parse error. The python resolver is LAZY (round MINOR-7 — no per-Stop interpreter spawn on machines that will never publish; the v5.8.0 spawn-tax class) and expands `MEGA_SDD_PY` unquoted per the resolver contract (round MINOR-8 — `py -3` machines).

**Round v6.19.1 (blind, 1 security lens): NO BLOCKER, 2 MAJOR + 8 minor/nit — all folded or dispositioned.** MAJOR-1 test hermeticity was HOME-only (Windows python reads USERPROFILE) → arms set both; MAJOR-2 session-vs-machine gap → condition (c); MINOR-3 f3 count assertion; MINOR-4 fall-through + scheme pins (f4b/f5b); MINOR-5 quoted-helper-path parsing (unquoted-path-with-spaces stays latent — mega-code writes the bare `mega-code get-token`, contract pinned at source-verification); MINOR-6 same-helper minting; MINOR-7 lazy resolver; MINOR-8 unquoted `MEGA_SDD_PY`; MINOR-9 `env -u` ambient-cleaning in test arms; MINOR-10 disclosure above; NIT-11 `utf-8-sig`.

**Tests (f-arms, all mutation-proved ×3 — signature loosened / env-match removed / scheme check removed each turn ≥1 arm red):** f1 vanilla session + foreign env → inert; f1b non-mega-code helper (a REAL shimmed binary, so the arm fails via the check, not via exec-failure) → inert despite a matching URL; f2 managed session (env matches settings) publishes, token absent from argv; f2c signature present but env absent → inert; f3 foreign env → ZERO POST (count-asserted); f4/f4b settings URL missing / scheme-less → inert; f5/f5b fall-through to config.yaml with signature absent AND with signature-but-no-URL. Pre-existing arms hermetic under scratch `HOME`+`USERPROFILE` and `env -u` cleaning.

## Amendment v6.19.2 — office governance: mega-code sessions MUST run mega-sdd (2026-08-20)

User mandate (office governance): any session provisioned through mega-code is REQUIRED to run the mega-sdd plugin. The plugin cannot enforce its own presence (absent plugin = no code runs), so enforcement lives at the two points that always run, with the plugin supplying deterministic detection signals:

1. **mega-code `get-token` guard (primary hard gate — their build):** apiKeyHelper is invoked for every token; before returning one, verify mega-sdd is installed+enabled → AUTO-REPAIR first (mega-code already auto-manages the plugin via `mega_sdd_latest`), refuse the token only when repair fails. No plugin → no token → no Claude Code.
2. **Gateway marker check (server-side, warn→block rollout — their build):** the detection contract is `mega-sdd-trace:session` (emitted by session-start on ALL paths, carried in every request body via history, re-injected after compaction, fires under `claude -p`) and `mega-sdd-trace:turn` (per prompt, `.mega-sdd` projects only). **The hard check MUST key on `:session`** — `trace_tag: false` suppresses only `:turn`; the routing opt-out (`~/.claude/.mega-sdd-routing-off` / `MEGA_SDD_ROUTING=off`) suppresses the session marker ONLY in CWDs with no SDD context, which the warn→block policy self-corrects (opted-out dev gets warned/blocked → removes the opt-out).
3. **Compliance reporting (ClickHouse/Langfuse + ingest):** per-NIP marker coverage, active repos without artifact publishes, and plugin version floor.

**Plugin-side change (this repo):** the publish manifest gains additive field `plugin_version` (read from the plugin's own `.claude-plugin/plugin.json`, fail-open to `""`) so the gateway can audit the version floor per NIP/project (the v5.9.0-floor lesson: "ask for the plugin version first"). Schema stays `mega-sdd-publish/1` (additive). Plus a contract-pin test for the `mega-sdd-trace:turn` emission + its documented opt-out (session-marker emission was already pinned in `tests/hooks/session-start.test.sh`). Marker strings are a STABLE GOVERNANCE CONTRACT — never rename. Docs: governance section in `keputusan-arsitek-gateway.md` + detection contract in `gateway-mcp-guide.md`. Verification scoped proportionally (additive fail-open field + doc/test pins): tests + mutation on the new arm, no full blind round.
