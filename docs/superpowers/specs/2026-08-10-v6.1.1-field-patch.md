## F1 — vault.json OQ ids count as declarations

`validate-handoff-binding-units.sh` builds `vault_oq_ids` from `<vaults>/vault.json` + `<vaults>/*/vault.json` (`open_questions[].tag` or `.id`, the 6.0.1 F5 dual-shape precedent) and the Pass-4 `oq_id_extra` advisory now checks `binding_oqs ∪ vault_oq_ids`. **Scope guarantees (round-verified against the whole validator):** every BLOCKING path is untouched — `oq_id_dropped` (binding LIVE bucket), conflict passes, recertify, and the PreToolUse gate (reads `status` only) never consume the new set; CONFLICT ids stay binding-only (vault.json structurally cannot inject them); unreadable/absent vault.json contributes NOTHING (fail-closed — the universe degrades to binding-only, never widens). Summary gains `oq_ids_in_vault`; the warning text now says "…or vault.json". Disclosed (recorded, consistent with the pre-existing cross-binding aggregation): `vault_oq_ids` is aggregated across vaults, and the advisory cannot distinguish which vault declared the id.

## F2 — the expects contract, taught at BOTH teachers

`unit-schema.md` states the substring contract (literal runner output or EMPTY; a description fails every run) and both its examples use the empty form; **`templates/unit.md` — the Step-10 scaffold every generated unit inherits — carries the same empty form + note** (round blocker: the first cut fixed the schema doc while the template kept stamping the poison into every new unit; template = fallback blast radius, the standing P4 lesson).
