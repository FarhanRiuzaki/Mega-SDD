# Iter 31 Design — v3.22.0 Full Pipeline Audit

**Status**: Design approved 2026-05-24
**Spec author**: Claude Opus 4.7 (via `superpowers:brainstorming` skill)
**User**: Farhan Riuzaki
**Plugin target**: NO version bump (audit-only iter). Closure deferred to Iter 32.

## 1. Problem statement

mega-sdd plugin reached v3.22.0 after 30 iterations. Recent surface additions (Iter 30 execute-bolts v2.6.0 tiered enrichment + propose-and-confirm + drift gate + 3 new reference files + 5 new halt types) are significant.

Pattern from prior audits:
- Iter 24 audit found 27 findings; Iter 25 closed them
- Iter 28 audit found 13 findings; Iter 29 closed them
- Both audits revealed "producer-only" pattern — feature iter ships producer-side; consumer skills oblivious; audit catches it; next iter closes propagation

Iter 30 explicitly tried to propagate within iter (all 3 affected skills bumped same iter). But other dimensions (stale paths, schema drift, examples coherence, halt taxonomy) may still have accumulated debt across 30 iters.

User directive: "audit all pipeline, in detail and in deep analysis." Iter 31 = comprehensive multi-dimensional audit.

## 2. Goals

1. **Multi-dimensional coverage** — 10 audit axes cover correctness, consistency, propagation, integration, anti-halu integrity
2. **Per-skill depth** — every skill audited individually (not just spot-checks)
3. **Cross-skill pattern detection** — identify issues spanning multiple skills
4. **Actionable output** — single AUDIT.md with prioritized findings + recommended Iter 32 closure scope
5. **Parallel execution** — 13 per-skill subagents + consolidator for fast wall-clock turnaround

## 3. Non-goals

- ❌ Fixing findings (deferred to Iter 32 closure iter)
- ❌ Cross-vault audit (different scopes' bolts → cross-scope drift) — too project-specific
- ❌ Vendored superpowers skills (`skills/_vendored/`) — upstream maintenance not mega-sdd concern
- ❌ Real-world field-test (user's tradefinance test is separate)
- ❌ Performance benchmarks (focus on correctness, not speed)
- ❌ Skill or plugin version bumps (audit-only iter)

## 4. The 10 audit dimensions

Each per-skill agent checks all 10:

| # | Dimension | What it catches |
|---|---|---|
| 1 | Version consistency | SKILL.md frontmatter version matches latest CHANGELOG claim |
| 2 | Stale path references | `docs/knowledge-base/`, `docs/mega-sdd/vaults/`, `.mega-sdd-memory/`, legacy paths as DEFAULTS (not back-compat notes) |
| 3 | Producer → consumer propagation | Schema fields declared by producer (vault.json `scope`, snapshot `bolt_self_report`) consumed by every downstream skill |
| 4 | Halt taxonomy consistency | Every halt fires in skill body appears in: (a) skill's halt section, (b) orchestrate-flow halt taxonomy, (c) handoff-contract.md if relevant |
| 5 | Schema / template consistency | YAML schemas in skill match canonical docs (vault-contract, handoff-contract, shared-snapshot-schema) |
| 6 | Spec-vs-implementation drift | Every CHANGELOG claim cross-checked against actual skill text — claimed but absent OR built but undocumented |
| 7 | Cross-references integrity | Every `references/X.md` and relative path link points to existing file |
| 8 | Examples coherence | Code/YAML examples use current syntax, current path conventions, current halt names |
| 9 | Integration health | Skill correctly cites cross-skill contracts (bind-codebase consumes generate-intent output; execute-bolts consumes generate-units output) |
| 10 | Anti-halu rail integrity | Every "halt on X" rule documented; binding gate non-negotiable; user-explicit confirmations preserved |

### Dimension prioritization

Within dimensions, severity logic:
- **P0**: claim-vs-implementation bug breaking workflow (e.g., halt referenced but procedure missing)
- **P1**: integration gap blocking compose (e.g., producer writes field, consumer doesn't read)
- **P2**: cleanup / minor inconsistency (e.g., wording variation, stale example)
- **Advisory**: worth noting (e.g., file getting large, unclear naming convention)

### 5.1 Per-skill audit subagent (13 instances)

Each receives skill name + full canonical reference list + 10 dimensions. Reads skill SKILL.md + references + commands + tests. Returns structured YAML findings.

**Per-skill scope**:
- `plugins/mega-sdd/skills/<name>/SKILL.md` (full read)
- `plugins/mega-sdd/skills/<name>/references/*.md` (all)
- `plugins/mega-sdd/commands/<name>.md` (if exists)
- `tests/skill-triggering/<name>.test.md` (if exists)
- `tests/scenarios/*.md` (grep for references to this skill)

**Canonical reference list** (read-only, used for cross-check):
- `plugins/mega-sdd/references/paths.md`
- `plugins/mega-sdd/references/shared-snapshot-schema.md`
- `plugins/mega-sdd/references/framework-conventions/*.md`
- `plugins/mega-sdd/skills/generate-intent/references/vault-contract.md`
- `plugins/mega-sdd/skills/orchestrate-flow/references/handoff-contract.md`
- `plugins/mega-sdd/skills/orchestrate-flow/references/routing-rules.md`
- `plugins/mega-sdd/skills/memory/references/memory-schema.md`
- `CHANGELOG.md` (last 5 iters relevant to this skill)

- tests/skill-triggering/<name>.test.md (if exists)
- tests/scenarios/*.md (grep for cross-references)

AUDIT DIMENSIONS — for each, scan + report findings:

1. Version consistency: SKILL.md `version:` vs CHANGELOG claims
2. Stale path references: legacy paths as DEFAULTS (not back-compat notes)
3. Producer → consumer propagation: schema fields written by skill consumed elsewhere?
4. Halt taxonomy: halts in body match halt section + orchestrate-flow taxonomy + handoff-contract
5. Schema/template consistency: YAML examples match canonical schemas
6. Spec-vs-implementation: CHANGELOG claims for this skill match actual procedure text
7. Cross-references: every `references/X.md` link resolves to existing file
8. Examples coherence: examples use current syntax/paths/halt names
9. Integration health: cross-skill contracts cited correctly
10. Anti-halu rails: halts on critical conditions present; binding gate intact; user-explicit confirmations preserved

OUTPUT FORMAT (single YAML block, structured for consolidator):

```yaml
audit_findings:
  skill: <skill-name>
  audited_at: <ISO8601>
  files_read: [<list of absolute paths>]
  findings:
    - dimension: <1-10>
      severity: P0 | P1 | P2 | Advisory
      title: <short description>
      file: <relative path>
      line: <line number or null>
      evidence: <verbatim quote or summary>
      suggested_fix: <one-line>
    - ...
  metrics:
    total_findings: <int>
    p0_count: <int>
    p1_count: <int>
    p2_count: <int>
    advisory_count: <int>
    dimensions_clean: [<list of dimension #s with 0 findings>]
  notes:
    - <any cross-cutting observation worth flagging to consolidator>
```

CONSTRAINTS:
- READ-ONLY: do NOT edit any files
- Cite exact file:line for every finding
- Be honest: if dimension is clean, list it under metrics.dimensions_clean
- Suggested_fix: one-line concrete action (not "investigate further")
- Max 200 lines findings per skill (truncate if more; flag in notes)
```

### 5.3 Consolidator agent

Receives all 13 per-skill YAML outputs. Produces single AUDIT.md per §6 structure.

**Cross-skill pattern detection rules**:
- Same halt name spelled inconsistently across ≥2 skills → pattern
- Same stale path appearing in ≥3 skills → systemic drift
- Producer → consumer propagation gap mentioned in ≥2 consumer skills → integration debt
- Same dimension generating findings in ≥4 skills → architectural concern (not skill-specific)

**Prioritization within AUDIT.md**:
- Findings table sorted by severity (P0 first)
- Cross-skill patterns surfaced BEFORE per-skill detail (most strategic insights at top)
- Recommended Iter 32 closure scope = top 5 fix areas with highest leverage

## 7. Acceptance criteria

Iter 31 audit ships when:

1. ✅ All 13 per-skill audit subagents dispatched in parallel + completed
2. ✅ Each per-skill agent returns structured YAML findings
3. ✅ Consolidator agent merges into single AUDIT.md
4. ✅ AUDIT.md covers all 10 dimensions across all 13 skills (dimensions × skills matrix = 130 cells; cells with 0 findings labeled clean)
5. ✅ Cross-skill pattern analysis section present (≥0 patterns surfaced; may be empty if none found)
6. ✅ Findings prioritized P0/P1/P2/Advisory
7. ✅ Recommended Iter 32 closure scope = top 5 fix areas with effort estimates
8. ✅ AUDIT.md committed to git (no plugin version bump)
9. ✅ NO actual fix changes made (audit-only iter per Goals §1)
10. ✅ Summary surfaces health verdict (GREEN/YELLOW/RED) + total findings count

## 8. Out of scope (deferred)

- Fixing findings → Iter 32 closure iter
- Cross-vault audit (different scopes' bolts → cross-scope drift)
- Vendored superpowers skills audit (upstream maintenance)
- Real-world field-test (user's tradefinance run)
- Performance benchmarks
- Plugin version bump (audit-only iter)
- Direct user-interactive triage (per user pick: audit-only output, not interactive)

## 9. Rollout

After Iter 31 ships AUDIT.md:

1. User reviews findings (no time pressure; audit is the deliverable)
2. User chooses Iter 32 closure scope:
   - Option A: accept consolidator's top-5 recommendation as-is
   - Option B: cherry-pick subset based on user priorities
   - Option C: defer some findings to Iter 33+ (e.g., big-rewrite recommendations)
3. Iter 32 brainstorms closure scope → ships fixes (subagent-driven-development)

## 10. Risk mitigation

| Risk | Mitigation |
|---|---|
| Per-skill agent over-reports (noise) | Cap findings at 200 lines per agent; flag in notes if truncated |
| Consolidator misses cross-skill patterns | Explicit pattern-detection rules (§5.3); review consolidator output for completeness |
| AUDIT.md too long to read | Cross-skill patterns + Iter 32 recommendation surfaced at top; per-dimension detail below |
| Parallel dispatch overwhelms API | Default 13-agent parallel dispatch acceptable per prior patterns; if rate-limited, fall back to 4-skill batches |
| Findings biased toward audited dimensions | Explicit 10-dimension checklist forces breadth; agent reports `dimensions_clean` so absence-of-finding is visible |
| Audit duplicates Iter 29 findings | Consolidator cross-references prior audit reports (`docs/superpowers/audits/2026-05-24-iter-28-v3.20.0-deep-audit.md` etc.) and flags duplicates |
