# mega-sdd Graph Layer — Design

**Date:** 2026-06-24
**Status:** Approved (brainstorm) — pending writing-plans
**Scope:** A derived, project-scope graph index over existing mega-sdd artifacts, with an impact/blast-radius query as the first lens.

---

## 1. Problem & framing

mega-sdd is *already* a graph — it just isn't explicit, queryable, or visualizable. The relational model exists today as scattered YAML frontmatter + markdown tables:

- Nodes: Units (`U-NNN`), Modules (`M-*`), KB Domains, Flows (`F-*`), ADRs (`D-*`), Binding Claims (`C-*`), OQs (`OQ-*`), Interfaces, Code Anchors (`file:line`).
- Edges: `depends_on` (unit→unit, domain→domain, with cycle-rejection already implemented), `blocks`/`blocked_by` (module→module), `consumes_interfaces`/`produces_interfaces` (unit→interface), `_source`/`_kb_source` (flow→KB file), binding anchors (claim→`file:line`), `binding_refs` (unit→C/OQ), `constitution_hash` (vault→clauses).

**Goal:** make that implicit graph explicit as a *derived lens* — not a new source of truth — and ship one high-value query first: **impact / blast-radius** ("code X changed → what units / modules / flows / KB domains are affected?").

**Non-goal (explicitly rejected):** authoring the KB *as* a graph (graph-DB replacing markdown). Markdown with `file:line` citations is the anti-hallucination moat; a graph that people author would create a second source of truth that drifts from the cited markdown. The graph is 100% derived.

## 2. Key insight that shapes the architecture

**Building the graph is cheap because we never re-scan code to build it.** Every edge already lives in artifacts (`binding.md` State Map → `C→file:line`; unit `binding_refs` → `U→C`; `modules.yaml` → `U→M`; `depends_on`; `_kb_source`). The builder is a pure parse of existing markdown/YAML.

Therefore the freshness risk is **not** "graph vs artifacts" (trivially fresh on rebuild) — it is **"artifacts vs code."** `binding.md` already carries a map-stamp. The graph inherits binding's staleness and must surface it on every answer.

## 3. Architecture

### 3.1 Storage — `.mega-sdd/graph.json`

- **Project-scope** (alongside `project.md` / `constitution.md`), because it spans KB + every vault + units + binding — wider than per-vault `vault.json`.
- A **pure cache**: marked `derived`, never hand-edited, safe to delete and rebuild. Same contract as `vault.json` (uneditable, regenerated).

### 3.2 Builder

- A deterministic script under the new skill's `references/` (or `scripts/`). Pure parse — no code re-scan, no LLM, no network.
- **Regenerated by:** (a) `sync` at the end of its reconcile (existing project-scope writer); (b) lazily by the query command when `graph.json` is missing or its `source_hashes` moved.

### 3.3 Schema (aligned to the de-facto graphify convention for interoperability)

Nodes:
```jsonc
{ "id": "U-007", "type": "unit", "label": "...",
  "attrs": { "module": "M-auth", "task_type": "create", "squad": "squad-backend" },
  "source": { "artifact": "<vault>/units/U-007.md", "field": "frontmatter" } }
```
Edges — `source`/`target`/`relation` + mandatory citation:
```jsonc
{ "source": "C-031", "target": "LoginController.php:45", "relation": "implements",
  "confidence": "VERIFIED",
  "evidence": { "artifact": "binding.md", "field": "Implementation State Map row C-031" } }
```

**Node types (v1):** `code_anchor`, `claim` (`C-*`), `unit` (`U-*`), `module` (`M-*`), `flow` (`F-*`), `kb_domain`, `oq` (`OQ-*`), `interface`, `vault`.

**Edge relations (v1):**
| relation | from → to | source field |
|---|---|---|
| `implements` | claim → code_anchor | binding State Map anchor |
| `honors` | unit → claim / oq | unit `binding_refs` |
| `depends_on` | unit → unit | unit `depends_on` |
| `in_module` | unit → module | `modules.yaml` vault_sections match |
| `blocks` | module → module | `modules.yaml` `blocks`/`blocked_by` |
| `kb_source` | flow → kb_domain | vault flow `_kb_source` |
| `domain_dep` | kb_domain → kb_domain | KB frontmatter `depends_on` |
| `covers` | claim → flow / vault-section | claim source location |
| `consumes` / `produces` | unit → interface | unit `consumes_/produces_interfaces` |

**Hard rule (anti-hallucination):** an edge exists **only** when a cited artifact field produces it. No inferred edges. Every edge carries `evidence: {artifact, field}`. A missing artifact yields a `[Pending]` node, never a fabricated edge.

### 3.4 Freshness gate (the spine — *gates > rules*)

```jsonc
"_meta": {
  "schema_version": "1.0",
  "derived": true,
  "built_at": "<ISO8601>",
  "head": "<git HEAD sha at build>",
  "source_hashes": { "<artifact path>": "sha256", ... },
  "binding_stamps": { "<vault-id>": { "map_stamp": "<sha>", "stale_vs_head": true } }
}
```

On every query:
1. If any `source_hash` differs from the on-disk artifact → **transparently rebuild** (artifacts are the truth; cache caught up).
2. **Always** compute `stale_vs_head` per binding (`map_stamp != HEAD`). If any is stale → **prepend a banner** to the answer:
   > ⚠ Blast-radius computed from a binding stamped `abc123`; HEAD is `def456`. Code may have moved since the last bind — anchors and impact may be incomplete. Run `/mega-sdd:sync`.

The graph never claims authority over code it has not re-bound. This is the property that makes a derived graph *safe* rather than a confident lie about traceability.

## 4. First lens — impact / blast-radius

Command: `/mega-sdd:graph --impact <anchor | U-NNN | C-NNN | domain-id> [--upstream | --downstream]`

- Typed BFS over the edges. Example downstream from a code path: `code_anchor → implements⁻¹ → claim → honors⁻¹ → unit → (depends_on⁻¹)* → unit → in_module → module`, plus `covers` / `kb_source` out to flows + KB domains.
- **Downstream** = "what breaks if I touch this." **Upstream** = "what this rests on."
- Output = blast radius grouped by node type, **each hit annotated with its cited edge chain**, plus the staleness banner when applicable.

## 5. Compliance with the v4 skills structure

| Invariant / doctrine | How graphify honors it |
|---|---|
| Anti-hallucination | Edges only from cited fields; missing artifact → `[Pending]`, never a fabricated edge |
| Citation discipline | Every edge + every impact answer carries an `evidence`/source chain |
| Derived & uneditable | `graph.json` = cache, regenerated, never authored (= `vault.json` contract) |
| Gates > rules > hooks | Freshness is a **gate** (rebuild-or-flag); the validation lens lands later as a gate |
| Halt taxonomy | Stale-vs-code → `sync` pointer; missing artifacts → partial graph, no fabrication |
| Lean skills + progressive disclosure | New lean skill `mega-sdd:graph` (SKILL.md ≤ 500 lines); schema + build algo in `references/` |
| Commands as entry points | `/mega-sdd:graph` |

**Footprint:** one lean skill + one command + one builder script + one schema reference. The only change to the existing pipeline is `sync` gaining an end-of-run `graph.json` regenerate. No new runtime dependencies.

## 6. Relationship to graphify (safishamsi/graphify) — v2 seam only

`safishamsi/graphify` is a separate YC-backed Python product (`graphifyy` on PyPI): tree-sitter AST + LLM-semantic extraction over the **code corpus**, producing `graph.json` / `graph.html` / `GRAPH_REPORT.md`, with Leiden clustering and Neo4j/FalkorDB export. Its skill is a thin wrapper over the `graphify` CLI binary.

- **Different layer.** graphify maps *what the code is* (AST + semantic). Our graph maps *what the spec demands and how it traces to code anchors*. Complementary, not competing.
- **Not the engine.** graphify emits **LLM-INFERRED** semantic edges — forbidden by our anti-hallucination moat — and a heavy Python/LLM-API dependency. v1 stays zero-dep and pure-derived.
- **Borrowed:** its node/edge JSON convention (`source`/`target`/`relation`/`confidence`) — adopted here for interoperability; and its EXTRACTED/INFERRED/AMBIGUOUS tier, which we already have natively as `[VERIFIED]/[INFERRED]/[OPEN]`.
- **v2 extension seam (reserved, not built):** optionally ingest graphify's `graph.json` as a *secondary* source to enrich the `code_anchor` layer with real call/import edges (deeper downstream impact). Gated hard — **EXTRACTED edges only, secondary evidence** (the same standing KB has under `codebase-map`), never trusted for INFERRED edges, never a required dependency.

## 7. Future lenses (designed-for, not built in v1)

The same derived `graph.json` is the substrate for:
- **Visualization** — render the graph (Mermaid / interactive HTML).
- **Global cross-artifact validation gate** — extend the existing cycle-rejection into a full gate: dangling refs (edge to a non-existent ID/anchor), orphan units, un-propagated OQs, broken anchors.

Both read the same file v1 produces; neither requires schema changes.

## 8. Testing

Fixture `.mega-sdd/` (mini KB + 2 vaults + units + binding) asserts:
1. Builder emits the expected nodes/edges, each with a resolvable `evidence` source.
2. Impact query returns the correct blast radius with cited edge chains (downstream and upstream).
3. Staleness banner fires when a binding `map_stamp != HEAD`.
4. Missing artifact → `[Pending]` node and **no** fabricated edge.
5. Deleting `graph.json` triggers a correct lazy rebuild on next query.
6. Source-hash change triggers transparent rebuild; unchanged hashes reuse the cache.

## 9. Open questions for planning

- v1 node scope: ship impact analysis with the full node set above, or the lean core (`code_anchor → claim → unit → module`) and add `flow`/`kb_domain`/`interface` with the coverage-gap lens? (Lean recommended; spec-side nodes carry their weight mainly for the coverage lens.)
- Builder language: shell + `jq`/`yq` vs a small Python script, matching how existing mega-sdd reference scripts are implemented.
