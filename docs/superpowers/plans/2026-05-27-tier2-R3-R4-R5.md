## R3: Conflict Classification Enrichment (bind-codebase)

**Surface:** [HOOK-VALIDATE] — extends existing `validate-vault-binding-coverage.sh`

### Task R3.1: Create `validate-conflict-classification.sh`

**Files:**
- Create: `plugins/mega-sdd/scripts/validate-conflict-classification.sh`

**Validation logic:**
- Parse `binding.md` or `binding-phase-*.md` for CONFLICT entries (regex: `| CONFLICT-\d+ |`)
- For each CONFLICT row: check if `conflict_class` column exists (semantic|naming|version|architecture)
- For each CONFLICT row: check if `resolution_complexity` column exists (trivial|moderate|significant)
- Missing field → WARN (not FAIL — backward-compatible with pre-R3 binding docs)

**Inputs:** `--cwd=<project> [--quiet]`
**Output:** `<cwd>/.mega-sdd/.conflict-classification-state.json`
**Exit:** 0=PASS, 1=FAIL

**Walking-skeleton slice:** Parse 1 CONFLICT from TF Import `binding-phase-2.md` → detect missing `conflict_class` field → WARN.

**Proof:** Run on TF Import; expect WARN (existing binding docs don't have these fields yet).

## R4: Domain-Rule GAP Detector (Mode B — KB-sourced only)

**Surface:** [VERIFY-STEP] — new `/mega-sdd:audit-rules` command

### Task R4.1: Create `audit-domain-rules.sh`

**Files:**
- Create: `plugins/mega-sdd/scripts/audit-domain-rules.sh`

**Validation logic:**
- Read `<cwd>/.mega-sdd/knowledge-base/40-business-rules/regulatory-rules.md`
- Extract all `[LOCKED]` entries (regex: lines containing `[LOCKED]` with rule description)
- Read `<cwd>/.mega-sdd/vaults/*/06-constraints.md` (active, non-archived)
- For each [LOCKED] KB rule: check if vault constraints reference the rule's key terms
- Key terms = extract nouns/identifiers after `[LOCKED]` marker
- Match = any constraint line in 06-constraints.md contains ≥50% of key terms
- No match → emit `RULE-GAP-{N}` with KB source + missing rule description
- Scope limit: ONLY runs when KB exists. No KB → exit 0 with "no KB, skip" message.

**Inputs:** `--cwd=<project> [--quiet]`
**Output:** `<cwd>/.mega-sdd/.domain-rules-state.json` + `<cwd>/.mega-sdd/RULE-GAP-REPORT.md`
**Exit:** 0=no gaps (or no KB), 1=gaps found

**Walking-skeleton:** Compare 1 [LOCKED] rule from TF Import KB `regulatory-rules.md` against vault constraints.

**Proof:** Run on TF Import; expect at least 1 gap (KB has more regulatory rules than vault explicitly constrains).

## R5: Constitution Enforcement Validator

**Surface:** [HOOK-VALIDATE] — new `validate-constitution.sh`

### Task R5.1: Create `validate-constitution.sh`

**Files:**
- Create: `plugins/mega-sdd/scripts/validate-constitution.sh`

**Validation logic:**
- Check if `<vault>/constitution.md` exists. If absent → SKIP (not all projects have constitutions).
- Compute sha256 of `constitution.md`
- Read `.handoff-validation-state.json` if present → check `constitution_hash` field matches actual hash
- Read `binding.md` if present → check any `constitution_violation` entries are flagged
- Walking-skeleton: sha256 hash check only (verify handoff carries correct hash)

**Inputs:** `--cwd=<project> [--quiet]`
**Output:** `<cwd>/.mega-sdd/.constitution-state.json`
**Exit:** 0=PASS/SKIP, 1=FAIL

**Walking-skeleton:** Hash check — compute constitution.md sha256, compare to handoff's `constitution_hash` field.

**Proof:** Projects without constitution.md → SKIP (clean). Project with constitution.md → hash matches or reports drift.
